# 豊臣大坂城、夜明けから日没までに立ち上がる

豊臣秀吉の大坂城（1580年代）が、夜明けから日没までの1日のタイムラプスで建ち上がっていく30秒（900フレーム・30fps）の3Dアニメーションを、Blenderで作るための設計とPythonスクリプトです。

外部アセットがなくても、スクリプトを1回実行すればシーン全体（地形・堀・石垣・本丸・天守・作業員・光・カメラ・テロップ）ができます。後から高品質な城モデル・人物・瓦テクスチャ・空のHDRIへ差し替えやすい構造にしてあります。

| ファイル | 内容 |
|---|---|
| `toyotomi_osaka_castle_timelapse.py` | Blenderのテキストエディタに貼り付けて実行するスクリプト（約3,200行・コメント多め） |
| `README.md` | この設計書 |

## 第2版で強化したところ

| 強化した点 | コードで実装したこと |
|---|---|
| 黒と金の天守 | すべての屋根に隅棟（四隅の稜線）を付け、反りを強めた。唐破風（曲線の破風）を二重目と四重目に追加。最上重は黒い柱で区切った金地の障壁画に。大棟に金の縁取り |
| 金箔瓦と金の鯱の反射 | 金箔を約11cm角の箔の継ぎ目と細かなきらめきで表現。軒丸瓦が並ぶ金の軒先。鯱は形を作り直し、鏡面に近い金と鱗の凹凸に。夕方に天守の上半分へ補助光。高品質版は強い反射に星形の光芒 |
| 石垣の不規則な石 | 大石のすき間に間詰石を詰める二段構えの野面積み。石の中央のふくらみ、水際の濡れと苔。四隅に長い隅石を交互に積む。高品質版は石を実際に凹凸させる（変位） |
| 堀の水面反射 | 大きなうねりと細かなさざ波の2層の波。粗さを下げて城と空をくっきり映す。EEVEEは平面プローブで鏡のように反射 |
| 朝・昼・夕方の空気感 | 霧の色・光芒の強さ・かすみを時刻で変える（朝は青白く光芒、昼は澄んで、夕方は金色にかすむ）。夜明けと夕方に鳥の群れが横切る |
| 作業員と資材の動き | 修羅（木ぞり）に巨石を載せて大勢で引く石曳き。石材・丸太が、使う場所まで運ばれてから消える。作業員は半透明でふっと現れて消え、歩くと上下する。石を置いた所に土埃。高品質版はモーションブラー |
| 最後の完成カット | 北西の堀の角から望遠で天守を見上げ、そこから引いていく。篝火が大手門から順に灯る。城下町に窓明かり。完成の瞬間に上下の黒帯（シネマスコープ）が入り、周辺減光で締める |

## すぐに使う

1. Blender 4.2以降を起動し、上部タブの **Scripting** を開く
2. テキストエディタの［開く］で `toyotomi_osaka_castle_timelapse.py` を選ぶ（または新規テキストに全文を貼り付け）
3. 先頭の `CFG` で、`PRESET` を `"LITE"`（軽量版）か `"HQ"`（高品質版）にする
4. ▶（スクリプト実行、Alt+P）。数秒でシーンが生成される
5. 3Dビューでテンキー0（カメラ視点）→ Spaceで再生
6. 書き出す前に `.blend` を保存し（出力先 `//render/` は .blend からの相対パス）、`CFG["QUALITY"] = "FINAL"` にして再実行 → Ctrl+F12

PNG連番をMP4にまとめる例：

```sh
ffmpeg -framerate 30 -i render/toyotomi_osaka_%04d.png -c:v libx264 -pix_fmt yuv420p -crf 18 toyotomi_osaka.mp4
```

再実行すると、前回このスクリプトが作ったもの（名前が `TS_` で始まるもの）だけを消して作り直します。自分で追加したオブジェクトは消えません。

## 軽量版と高品質版

`CFG["PRESET"]` で切り替えます。各項目は `CFG` に値を書けば個別に上書きできます（例：`"PRESET": "HQ"` のまま `"ENGINE": "EEVEE"`）。

| 項目 | 軽量版 `LITE` | 高品質版 `HQ` |
|---|---|---|
| 想定 | 作業中の確認、SNS向けの短い納期、ノートPC | YouTube向けの本番、作品としての書き出し |
| レンダラー | EEVEE（サンプル32） | Cycles（サンプル384・ノイズ除去・適応サンプリング） |
| 石垣 | バンプ（見た目だけの凹凸） | 細分化＋変位で石を実際に凹凸させる（約34万面） |
| 水面の反射 | 平面プローブ（EEVEE） | レイトレース（Cycles） |
| 霧 | ボリューム（影なし・粗いタイル） | ボリューム（光芒の影あり・細かいタイル） |
| 動き | モーションブラーなし | モーションブラー（シャッター0.5） |
| 篝火 | 炎の発光だけ（12基） | 炎＋点光源で周囲を照らす（18基） |
| グレア | ブルーム | ブルーム＋星形の光芒 |
| 量 | 作業員110・町家90・松50・牛車4・石曳き2組・鳥14・土埃28 | 作業員200・町家160・松90・牛車6・石曳き3組・鳥30・土埃60 |
| オブジェクト数 | 約1,800 | 約2,200 |

`QUALITY = "PREVIEW"` にすると、どちらのプリセットでも解像度50%・サンプル1/4で素早く確認できます。

**重さの目安（実測はCPUのみ）：** GPUのない環境（CPU 4コア、Blender 5.2）で測った値です。

| 条件 | 1フレームの時間 |
|---|---|
| 高品質版・Cycles・480×270・8サンプル | 約4〜6秒 |
| 高品質版・Cycles・960×540・12サンプル | 約18〜27秒 |
| 軽量版の内容をCyclesで・480×270・6サンプル | 約3.3秒 |
| 軽量版・EEVEE（GPUなしのソフトウェア描画）・480×270 | 約13〜18秒 |

GPUでは、EEVEEは大幅に速くなるはずです。ただしGPUでの速度は実測していません。本番（1920×1080）は解像度が16倍になる点も見込んでください。

## 1. 全体設計

### 考え方

- **1本の長回し。** 何年もかかった築城を、1日の光の変化に重ねて30秒に圧縮します。時間の経過は、太陽の移動・空の色・影の向き・作業員の動き・資材の増減・建物の出現で見せます。
- **手続き生成＋スケジューラー。** 建物の部材はすべてPythonで生成し、各オブジェクトに「いつ・どう現れるか」をカスタムプロパティ（`b_start` など）として書き込みます。最後に `apply_build()` がそれをキーフレームに変換します。
  - 演出を直すときはプロパティ（数字）を変えるだけで済みます。
  - 差し替えたモデルにも同じプロパティを付ければ、同じように建ち上がります。
- **アセットはインスタンス配置。** 作業員・牛車・町家・松・鯱は、非表示のアセット用コレクションの中身をインスタンスで並べています。中身を入れ替えれば、シーン中のすべてが置き換わります。
- **黒と金を主役に。** 周囲（石垣の灰色、漆喰の白、草地の緑、空の青）は控えめな色にし、天守の黒漆と金箔瓦のコントラストが最も強く見えるように色を組んでいます。

### 配置（単位m、+X=東、+Y=北）

```

   ┌─────────────────── 堀の外形 280×250（水面 -2.2m / 堀底 -6m）───────────────┐
   │      ┌──────────────── 本丸（下段）180×150・上面 +10m ────────────────┐      │
   │      │ 櫓                                                       櫓 │      │
   │      │        御殿B    ┌──── 詰ノ丸（上段）90×75・+16m ────┐       │      │
   │ 西 │ 櫓 │                │ 櫓     御殿C       ■天守台・天守 │ 櫓 │ 東 │
   │      │                 │ 櫓                        櫓 │       │      │
   │      │   御殿A          └───────────────────────┘       │      │
   │      │ 櫓              幟・千成瓢箪   【大手の櫓門】            櫓 │      │
   │      └──────────────────────────────┼─────────────────────┘      │
   └──────────────────────────────────┼ 木橋 ──────────────────────────┘
```

- 天守は史実に倣い、本丸の北東寄り（詰ノ丸）に置いています（`L["TENSHU_C"]` で変更可）。
- 天守は外観五重で、天守台と鯱を含めた高さは地面から約66mです。

## 3. アニメーション設計

### タイムライン（30fps・900フレーム）

| フレーム | 時刻 | 起きること |
|---|---|---|
| 1〜150 | 夜明け | 朝霧の更地と台地。木杭が打たれ、縄が張られる（12〜130）。石材が運び込まれて増える。作業員がふっと現れて動き始める。牛車が街道を往復。烏の群れが横切る（30〜175）。タイトル（8〜112） |
| 150〜300 | 朝 | 堀を4辺順に掘る（150〜245）。本丸の石垣が4面それぞれ下から石1個ずつ積み上がり、隅石も積まれる（160〜298）。外側の石垣（175〜285）。水が満ちる（235〜300）。詰ノ丸の石垣（250〜330）。石曳きの組が巨石を堀端へ運び、着くと土埃。クレーンが旋回。石材が堀端へ運ばれて減る |
| 300〜500 | 昼 | 木橋（300〜332）、高麗門、大手の櫓門（335〜375）。塀が周囲に伸びる（340〜470）。櫓9基（360〜490）。本丸御殿3棟（420〜495）。幟と篝火の台が立つ（470〜495）。丸太が普請場へ運ばれて減る。詰ノ丸で天守台へ巨石を運ぶ石曳き（466〜540） |
| 500〜750 | 午後 | 天守台を積む（500〜536）。天守を一重ずつ（520から40フレームごと）：床→足場→柱→梁→黒漆の壁→窓・金の帯→野地→瓦と隅棟→破風→金の軒丸瓦・鬼瓦（きらめき）。最上重は高欄→金の障壁画→黒い柱。大棟と金の縁取り（722〜729）、金の鯱（728〜736）。足場を上から外す（736〜758）。城下町が建ち始める（590〜） |
| 750〜900 | 夕方 | 完成。上下に黒帯が入る（752〜786）。補助光と夕日で天守が金色に輝き、鯱・鬼瓦・千成瓢箪がきらめく。篝火が大手門から順に灯る（792〜）。町家の窓明かり（795〜）。烏の群れ（765〜900）。北西の堀の角から見上げ、引いてワイドに。締めのテロップ（826〜） |

### 出現のしかた（`b_mode`）

スケール・透明度・位置の各アニメーションを組み合わせて、「地面から立ち上がる」ように見せます。

| モード | 動き | 使っている所 |
|---|---|---|
| `reveal` | マテリアルのマスクで、下から上へ積み上がる（伸び縮みしない） | 石垣（石1個ずつ）、天守の壁・瓦・隅棟、櫓・御殿の壁 |
| `grow` | 底面（または端）を基準に、指定の軸方向へ伸びる | 柱、塀、縄、足場、橋 |
| `drop` | 上から降りながらフェードイン | 屋根、野地、隅棟 |
| `rise` | 下からせり上がりながらフェードイン | 水面、床、門 |
| `pop` | 弾むように現れる（1.12倍まで行き過ぎて戻る） | 金の装飾、窓、資材、町家、幟、隅石、破風 |
| `fade` | 透明から不透明へ | 町の通り |

消え方（`b_end_mode`）は、次の5種類です。

- `shrink`：縮んで消える（資材・足場）
- `sink`：沈む（掘削前の地面）
- `carry`：`b_end_target` の場所まで運ばれてから消える（石材・丸太）
- `fade`
- `none`

石垣の `reveal` では、ボロノイの各セル（石1個）の中心の高さで判定します。そのため、石が1個ずつ置かれていくように積み上がります。

### タイムラプス感の作り方

- **作業員：** 時間帯ごとの持ち場（夜明けは南の置き場と台地、朝は堀の周り、昼は本丸、午後は詰ノ丸と天守の足場、夕方は城下）に現れます。
  - 5〜14フレームで小移動しては立ち止まり、30〜80フレームで消えて別の場所に現れます。
  - 現れるときと消えるときは4フレームかけて半透明になるので、タイムラプス写真の人のように見えます。インスタンス元の `b_itransp` を、マテリアルがInstancer属性で読んでいます。
- **石曳き：** 1往復を約2秒に縮めています。着いたら石を置いて（消えて）土埃が上がり、また次の石を運んできます。引き手は綱を引くように体を揺らします。
- **資材：** 石材は夜明けに増えます。朝になると半分ほどが堀端・本丸の縁・天守台のふもとへ運ばれ、そこで消えます。丸太は昼から午後にかけて、橋のたもとや本丸の普請場へ運ばれて消えます。
- **雲と影：** 雲が速く流れ、地面を雲の影が走ります。
- **光：** 太陽の方位が68°から268°まで動き、影が大きく回ります。

## 4. マテリアル設計

建物用のマテリアルには、すべて共通の **建設マスク**（ノードグループ `TS_BuildMask`）を組み込んでいます。マスクはカスタムプロパティをAttributeノードで読みます。

| プロパティ | 読む場所 | 意味 |
|---|---|---|
| `b_transp` | オブジェクト | 0＝不透明、1＝透明（フェード） |
| `b_reveal_on` / `b_reveal_z` | オブジェクト | 1のとき、ワールド高さ `b_reveal_z` より上を隠す（積み上がり） |
| `b_itransp` | インスタンス元（Instancer） | 作業員のふっと現れる・消える半透明 |
| `b_glint_v` | オブジェクト | 金箔の発光パルス（きらめき） |
| `b_flick` | オブジェクト | 篝火の炎の揺らぎ |
| `band_z` | オブジェクト | 漆喰マテリアルで、この高さより下を黒い腰板にする |

| マテリアル | 見た目 | 作り方 |
|---|---|---|
| `TS_KuroUrushi` 黒漆 | ほぼ黒（0.01）、クリアコートでつや | ワールドZの正弦波で下見板（横板）の凹凸 |
| `TS_Kinpaku` 金箔 | 金の反射色（1.0, 0.77, 0.34）・金属1.0 | Brickテクスチャで約11cm角の箔の継ぎ目（継ぎ目は少し暗く粗い）。高周波ノイズで細かなきらめき。発光＝`b_glint_v`×14＋`GoldGlow`（夕景） |
| `TS_KinpakuTile` 金箔瓦 | 軒先に丸瓦の先端が並ぶ | 金箔＋面の向きで列方向を切り替える丸い凹凸 |
| `TS_KinpakuMirror` 鯱 | 鏡面に近い金（粗さ0.09） | 金箔＋ボロノイの鱗 |
| `TS_KinpakuPaint` 障壁画 | 金地に墨と緑青の筆致 | ノイズのしきい値で絵の面と線を作り、その部分だけ金属を外して粗くする |
| `TS_Kawara` 瓦（いぶし瓦） | 暗い青灰、金属0.35 | 面の向きで丸瓦の列方向を切り替える正弦波バンプ＋段のバンプ |
| `TS_Ishigaki` 石垣（野面積み） | 大石と間詰石、灰〜茶、水際は濡れて苔 | 大石（約2m×1.3m）と小石（約0.6m×0.45m）のボロノイを重ね、大石のすき間だけ小石にする。石ごとに色を変え、中央をふくらませる。水面付近は暗く滑らかに、苔をのせる。高品質版は同じ高さ情報で変位 |
| `TS_IshigakiBlock` 隅石 | 大きな切石 | ノイズの色むらとバンプ。水際は濡れる |
| `TS_Water` 堀の水 | 深い青緑、粗さ0.02 | 4Dノイズ2層（うねり・さざ波）を時間で動かす。Layer Weightで正面は暗く、斜めは反射寄り |
| `TS_Fog` 朝霧 | 地表ほど濃いボリューム | 密度（`FogDensity`）・色（`FogColor`）・前方散乱（`FogAniso`）・かすみ（`FogHaze`）を時刻でキー |
| `TS_TownWindow` 町家の窓 | 夕方に暖色で灯る | 発光の強さ `WindowGlow` をキー |
| `TS_Flame` 篝火 | 橙の発光、縁は透ける | `b_flick` で強さが揺らぐ |
| `TS_Dust` 土埃 | 縁ほど透明な土色 | Layer Weightで柔らかい縁 |
| `TS_Vignette` 周辺減光 | 四隅ほど黒 | カメラ前の板に、中心からの距離で透明度を付ける |
| その他 | 漆喰・地面・檜皮葺・遠山・白木・古材・縄など | 第1版と同じ |

透明を使うもののうち、土埃・炎・周辺減光は、EEVEEで「ブレンド」方式にしています。「ディザ」方式のままだと、画面を覆う周辺減光の板が粒状のノイズになるためです。

**テクスチャの差し替え：** `CFG["TEXTURES"]` に画像のパスを書くと、`kawara`・`ishigaki`・`kuro`・`shikkui`・`wood`・`ground` のベースカラーが、ボックス投影の画像に置き換わります。

### 差し替えのしかた

- **作業員・牛車・町家・松・鯱：** `TS_99_ASSETS_差し替え用` の中の `TS_ASSET_xxx` コレクションの中身を、自分のモデルに入れ替えるだけです（原点＝足元、正面＝+Y、作業員は身長約1.7m）。全インスタンスが自動で置き換わります。
  - 作業員の「ふっと現れる」半透明を残したい場合は、差し替えたモデルのマテリアルの最後に、ノードグループ `TS_BuildMask` を通した透明とのミックスを入れてください（`TS_` のマテリアルを割り当てるのがいちばん簡単です）。
- **天守・櫓などの建物：**
  1. 高品質モデルを読み込み、生成された `TS_04_天守` を非表示にする
  2. 自分のモデルの部品に、カスタムプロパティ `b_start`（開始フレーム）・`b_dur`（長さ）・`b_mode`（`reveal` など）を付ける
     - 手作業が大変なら、スクリプトの関数 `auto_schedule_by_height(オブジェクト一覧, 520, 725)` を使うと、低い部品から順に自動で割り振れる
  3. 部品に `TS_` のマテリアル（`TS_KuroUrushi`・`TS_KinpakuTile`・`TS_Kawara` など）を割り当てると、`reveal` やきらめきがそのまま効く
  4. `CFG["MODE"] = "ANIM_ONLY"` にして再実行する（建物は作り直さず、アニメーションだけ付け直す）
- **空：** `CFG["HDRI_PATH"]` に夕景・朝焼けのHDRIを指定します。

## 8. 手作業で追加する手順（コードだけでは難しい部分）

効果の大きい順に並べています。どれも、スクリプトで生成した後の `.blend` に対して行う作業です。**作業後に再実行する場合は `MODE = "ANIM_ONLY"` を使ってください**（`FULL` だと `TS_` の付いた物は作り直されます）。

### 8-1. 天守のヒーローモデル化（570〜840フレームで大きく映る）

1. 生成された `TS_04_天守` を複製してから作業する（Shift+D → M で新しいコレクション `MyTenshu` へ）。複製したものは `TS_` で始まらない名前に変える
2. **唐破風：** `TS_Tenshu1_karahafu` を編集モードで開き、破風板の曲線に沿って懸魚・兎の毛通しの彫刻を追加する（Curve → メッシュ化、またはスカルプト）
3. **華頭窓：** 上二重の窓 `TS_Tenshu3_win*`・`TS_Tenshu4_win*` を、釣鐘形の華頭窓に置き換える（ベジェ曲線で輪郭を描き、押し出して金の枠にする）
4. **瓦の実形状：** 丸瓦1本を作り、配列（Array）モディファイア＋カーブ（Curve）モディファイアで、屋根の斜面に沿って並べる。近景だけでよいので、最上重と四重目の正面に絞ると軽い
5. **障壁画：** 最上重の `TS_Tenshu4_panels` に、虎・鶴などの絵の画像（自作や権利の明確な素材）を `TS_KinpakuPaint` のベースカラーとして貼る（UV展開 → 画像テクスチャ）
6. 部品に `b_start` などを付けるか、`auto_schedule_by_height()` で割り振り、`TS_04_天守` を非表示にして `ANIM_ONLY` で再実行する

### 8-2. 金の鯱をスカルプトで作る

1. `TS_ASSET_shachi` コレクションの中身を非表示にし、新しいUV球を置く
2. スカルプトモード（Dyntopo、詳細8〜12px）で、頭・反った胴・扇形の尾・ひれを作る。資料は名古屋城などの現存する鯱の写真が参考になる
3. 鱗はブラシ（Draw Sharp）か、ボロノイのディスプレイスメントで入れる
4. マテリアルに `TS_KinpakuMirror` を割り当て、原点を足元、頭を +X 向きにして `TS_ASSET_shachi` に入れる。2体とも自動で置き換わる

### 8-3. 石垣を写実的にする

- **実写素材：** 石積みのPBRテクスチャ（Poly Havenなど、ライセンスを確認したもの）のカラー・ラフネス・ディスプレイスメントを用意する。`TS_Ishigaki` のボロノイの代わりにつなぎ、高品質版の変位にディスプレイスメント画像を使う。積み上がり（`reveal`）は、マスクの高さ入力に `Geometry > Position` のZをつなげば、石単位でなく行単位で動く
- **石を立体で並べる：** 石垣の面にジオメトリーノードの「面に点を配置」で点を撒き、「インスタンスを点に」で数種類の石のメッシュを並べる。数万個になるので高品質版のみ。前景（700〜840フレームで映る西面・北面）だけに絞ると現実的

### 8-4. 作業員をリグ付きの人物にする

1. 権利の明確なリグ付きの人物（身長1.7m前後）を用意し、歩く・担ぐ・引くのアクションを付ける（Mixamoなどの書き出し規約を確認）
2. 小袖・陣笠などの衣装に着せ替える
3. アクションをNLAで繰り返し再生できるようにし、`TS_ASSET_worker_a`〜`d` の中身と置き換える
4. 移動はスクリプトの軌跡（インスタンスのキーフレーム）がそのまま使える。歩く速さに合わせて、NLAストリップの再生速度を調整する
5. 大量に並べると重いので、遠景はスクリプトの簡易な人型のまま残し、カメラに近い人だけ差し替えるのがおすすめ

### 8-5. 布・煙・炎のシミュレーション

- **幟：** 布の板（`TS_Nobori*_cloth`）のWaveモディファイアを外し、Clothシミュレーションに替える。竿側の頂点をピン留めし、Force Fieldの風（強さ200〜500）を当てる
- **土埃・炊煙：** 石曳きの到着点や石垣のふもとに、物体 → クイックエフェクト → クイック煙。煙の色を土色にし、数十フレームで消えるよう放出量にキーを打つ
- **篝火：** `TS_Fire*_flame` を、クイック煙（炎と煙）に差し替える。高品質版の点光源（`TS_Fire*_light`）は残す

### 8-6. 空と雲

- **HDRI：** 朝焼け・日中・夕焼けのHDRIを3枚用意し、`build_world()` の環境テクスチャをミックスシェーダーで切り替える（混合率に時刻のキーを打つ）
- **ボリュームの雲：** 雲のメッシュ（`TS_Cloud*`）のマテリアルを、プリンシプルボリューム（密度20〜50＋ノイズ）に替える。重いので高品質版の夕景カットだけでも効果がある

### 8-7. カメラの仕上げ

- **手持ち感：** カメラの親に空のオブジェクトを入れ、そのX・Y回転にノイズのFカーブモディファイア（強さ0.002〜0.004、スケール30）を付ける。完成カット（805〜900）だけ強めると臨場感が出る
- **被写界深度：** 805〜840フレームで、天守にピントを合わせ（F値4〜5.6）、手前の石垣を少しぼかす。テロップがぼけるので、テロップは編集ソフトで入れる（`USE_TITLES = False`）

### 8-8. 色の仕上げと音

- **グレーディング：** DaVinci Resolveなどで、次のように仕上げる
  - 黒を締め、金の彩度を少し上げる
  - 朝は青、夕方は橙に寄せる
  - コンポジターで行う場合は、カラーバランスとRGBカーブのノードを、グレアの後ろにつなぐ
- **音：** 次のような効果音とBGMを付けると、30秒の満足感が大きく変わります。
  - 朝：鳥の声・槌音
  - 石曳き：掛け声・木やり
  - 午後：瓦を葺く音
  - 夕方：太鼓・鐘

### 8-9. 書き出し

- PNG連番で書き出し、ffmpegでまとめる（上のコマンド）。途中で止まっても、出力済みのフレームから再開できる
- 4Kにする場合は、`resolution_percentage = 200`。重い場合は1080pで書き出して、編集ソフトでアップスケールする

## 史実について（どこまで史実で、どこから演出か）

- **築城：** 天正11年（1583）に築城開始。天守は天正13年（1585）頃に完成したとされます。本丸の外側（二の丸・三の丸・惣構え）の工事は、その後も長く続きました。
- **天守の姿：** 「大坂夏の陣図屏風」（大阪城天守閣蔵）などの絵画資料と、出土した金箔瓦から推定されている姿を参考にしました。黒漆塗りの壁、金箔瓦、金の飾り、外観五重です。内部の階数や細部の意匠（破風の数と位置、最上重の装飾など）には諸説あり、この映像は推定を元にした「豊臣大坂城らしさ」の表現です。
- **天守の位置：** 本丸の北東寄りにあったとされるため、詰ノ丸の北東に置いています。
- **本丸：** 上段（詰ノ丸）と下段の二段構えを簡略化して表現しています。
- **石垣：** 豊臣期の石垣は、自然石を積む野面積みとされています。現在見られる大きく整った石垣は、徳川期に築き直されたものです。隅石の積み方は演出として整えています。
- **今の大阪城との違い：** 現在の天守（1931年に復興）は、豊臣期と徳川期の意匠を合わせたものです。徳川期の天守は白壁でした。この映像は、それとは違う「黒と金」の豊臣期の姿を描いています。
- **規模：** 実際の豊臣大坂城は、三の丸・惣構えまで含めると、はるかに広大でした。映像では本丸周辺に絞り、縮尺も簡略化しています。
- **演出として加えたもの：**
  - 千成瓢箪（秀吉の馬印として知られる）、幟の色、本丸御殿の檜皮葺の屋根
  - 城下町の配置（のちの船場・上町を意識）
  - 唐破風の位置、篝火、石曳きの組の人数
  - 1日に圧縮した工程の順番
  - 完成カットの補助光

## 動作確認

- Blender 4.2.23 LTS・4.5.15 LTS・5.2.3 LTSで、軽量版・高品質版ともスクリプトの実行とCyclesのレンダリングを確認しました。Blender 5.2では、軽量版のEEVEEのレンダリングも確認しています。
- 確認はGPUのない環境で行いました。そのため、レンダリング時間の実測値はCPUでのものだけです（上の「重さの目安」）。GPUでの速度は未計測です。
- 生成にかかる時間は、軽量版で約1.8秒（約1,800オブジェクト）、高品質版で約2.0秒（約2,200オブジェクト）でした。
- 同じ.blendで2回続けて実行してもオブジェクトが増えないこと、自分で置いたオブジェクトが消えないこと、`ANIM_ONLY` モードで再適用できることを第1版で確認しています。縦型（9:16）でも生成と描画を確認しています。
- Cyclesの「永続データ（Persistent Data）」はオフのまま使ってください（スクリプトでもオフにしています）。第1版の検証で、オンのまま全900フレームを連続レンダリングすると、建設マスクの値が食い違って、ところどころのフレームで石垣が透けました。
